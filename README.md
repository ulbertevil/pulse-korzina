# Пульс «Корзины доброты»

> Проект для конкурса X5 «Вайбкодинг добрых дел» (фонд X5 «Выручаем»). В разработке.

**Что это.** Инструмент для фонда «Выручаем», который отвечает на вопросы: сколько соберём на следующей акции «Корзины доброты», в какие магазины и в какие часы ставить волонтёров, какие магазины собрали меньше ожидаемого и как проверить новую механику A/B-тестом.

Комплементарен «Карте продовольственного разрыва» (куда направлять помощь) и «Корзине рядом» (где сдать продукты): «Пульс» отвечает, когда, где и сколькими силами собрать больше.

## Бэктест (на синтетике)

Учим на акциях до t, прогнозируем акцию t; 5 шагов, от 1 237 до 1 740 магазинов.

| Модель | WAPE по магазинам | Ошибка суммы по сети | К наивной |
|---|---|---|---|
| GLM + эмпирический Байес | **29,4%** | 7,5% | **−25%** |
| Экспоненциальное сглаживание | 34,0% | 16,7% | −13% |
| Сезонная наивная | 37,4% | 9,2% | −5% |
| Наивная («как в прошлый раз») | 39,2% | 19,7% | — |

Интервалы магазина: 80% накрывают в среднем ≈78% фактов, 95% — ≈93%.

**Важно:** это проверка того, что конвейер работает и модель находит заложенные эффекты. Это не оценка точности на реальных данных: модель и синтетика устроены похоже, поэтому на настоящих данных фонда ошибка будет выше. Честная точность появится после загрузки выгрузки фонда.

## Модель

`glm_eb`: квазипуассоновская лог-линейная регрессия (сезон, тренд, число часов, дни недели, волонтёры с убывающей отдачей, сеть, размер города), умноженная на эмпирико-байесовский множитель магазина. У магазина с короткой историей прогноз ближе к его региону, с длинной — к его собственному уровню. Коэффициенты сезона и тренда сжимаются априорным штрафом, потому что акций в истории немного. Код — numpy, без тяжёлых зависимостей, чтобы перенести его в браузер.

## Как запустить

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/build.py   # данные, синтетика, бэктест, прогноз
.venv/bin/python -m pytest -q       # 18 тестов
```

## Принципы

- Все публичные цифры — в `data/facts.csv` со ссылкой на источник и датой. Статусы: `primary` (первоисточник), `secondary` (СМИ), `fund_statement` (заявление фонда), `unverified`, `estimate`.
- Оценки и допущения помечены как оценки. Синтетические данные помечены везде, где показаны.
- Ядро будет работать на выгрузке фонда формата «магазин, дата/час, кг» прямо в браузере, без сервера и персональных данных.
