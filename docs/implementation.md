# Как внедрить «Пульс» в фонде «Выручаем»

Коротко: страница статическая, расчёт идёт в браузере, персональные данные не нужны. Для запуска достаточно выгрузки сборов, которая у фонда уже есть, и одного аналитика на пару часов перед каждой акцией и после неё.

## Кто что получает

| Кто | Что видит | Где |
|---|---|---|
| Руководитель фонда | Сколько соберём на акции, сколько это наборов, с каким разбросом; сколько волонтёров набрать под цель и в каких городах | «Следующая акция», «Цель», ссылка `?goal=160` |
| Координатор города | Лист на акцию: магазины, часы, сколько людей поставить, на сколько кг готовить тару | «Мой город», ссылка `?city=Казань` |
| Аналитик фонда | Точность на своих данных, план-факт, магазины ниже ожидаемого, дизайн эксперимента | «Свои данные», «A/B», `scripts/build.py` |

## Какие данные нужны

1. **История сборов** — одна строка на магазин в день акции: магазин (адрес или ID), дата, кг. Желательно ещё часы работы точки и сколько волонтёров стояло. Формат и пример — в README («Посчитать на своих данных») и в `site/template.csv`. По данным фонда, собранное фиксируется сканированием в приложении волонтёра, так что выгрузка уже существует.
2. **Таблица магазинов следующей акции** — та, что фонд публикует для волонтёров (адрес, даты, часы). Подключается кнопкой «Новая акция» в GitHub Actions (`scripts/new_action.py`): расписание разбирается автоматически (11 форматов записи), строки, которые не удалось разобрать, перечисляются в отчёте. Если разобрано меньше 90% строк, сайт не меняется.

Имена волонтёров, телефоны и другие персональные данные не нужны: только магазины, даты, часы и килограммы.

## Цикл одной акции

| Когда | Что делаем | Сколько времени |
|---|---|---|
| Один раз | Загрузить историю на странице, посмотреть точность против «как в прошлый раз». Если модель не лучше — дальше не идём | 1 час |
| За 2 недели | На GitHub: Actions → «Новая акция» → вставить ссылку на таблицу магазинов. Таблица проверится (отчёт — на странице запуска), прогноз, расстановка и листы координаторов пересчитаются, сайт опубликуется сам | 5 минут |
| За 2 недели | Задать цель акции на странице, скачать список «где нужны новые смены» и передать его в набор волонтёров | 15 минут |
| За 10 дней | Разослать координаторам ссылки на листы их городов; координатор кнопкой копирует готовый текст для чата волонтёров | 30 минут |
| После акции | Загрузить новую выгрузку: план-факт, список магазинов ниже ожидаемого — разобрать с координаторами | 1 час |
| Раз в полгода | Эксперимент: одна идея на списке «тест / контроль», итог после акции | 2 часа |

## План пилота

1. **Декабрь 2026.** Прогноз на 10–11 декабря зафиксирован заранее (`forecasts/2026-12-10.md`). Сравниваем с итогом фонда.
2. **Январь 2027.** Фонд передаёт историю сборов по магазинам. Перекалибровка на реальных данных, отчёт о точности.
3. **Весенняя акция 2027.** Листы координаторам в 3–5 городах, где у фонда есть активные координаторы. В остальных городах расстановка как обычно — это заодно сравнение.
4. **Летняя или осенняя акция 2027.** Эксперимент «+1 волонтёр» — измерить эффект, который сейчас модель только оценивает.

## Как понять, что работает

- Ошибка прогноза по магазинам на реальных данных ниже, чем у «как в прошлый раз» (на синтетике −25%).
- Сумма по сети попадает в 80% интервал примерно в 8 акциях из 10.
- В городах пилота килограммов на одну волонтёрскую смену больше, чем в остальных.
- Эксперимент дал оценку эффекта волонтёра с интервалом.

## Риски

| Риск | Что делаем |
|---|---|
| Эффект волонтёра в жизни меньше, чем оценила модель | В проверенных сценариях (эффект от нуля до вдвое больше оценки) расстановка не хуже текущей (раздел «Реальность»); эксперимент его измерит |
| В выгрузке пропуски или разные форматы | Проверка файла показывает, сколько строк взято и почему пропущены остальные; синонимы колонок и форматы дат распознаются |
| Новый магазин без истории | Прогноз берётся по региону и сети |
| Декабрьских акций в истории нет | Декабрь моделируется как ноябрь; после первой декабрьской акции сезон оценится |

## Техника

- Сайт — статические файлы `site/`, можно разместить на GitHub Pages или любом хостинге фонда.
- Расчёт на странице — `site/model.js`, тот же алгоритм, что в Python (`pulse/`); совпадение проверяет тест.
- Полный конвейер — `scripts/build.py`, Python 3 + numpy + pandas. Автотесты — `pytest`, проверка при каждом изменении в GitHub Actions; перед публикацией сайт открывается в headless Chrome и проверяется на ошибки.
